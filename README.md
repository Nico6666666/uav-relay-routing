# UAV Transport–Relay Scheduling: Code and Experiments

This repository provides the code and experiments for our study on heterogeneous
UAV relief logistics under continuous communication constraints, covering payload
and batching analysis, multi-point multi-sortie scheduling, joint transport–relay
scheduling, and task partitioning with resource accounting.

English README: [README_EN.md](README_EN.md)

## 1. 功能概览

代码按四层任务组织，上游输出供下游读取：

| 任务 | 求解内容 | 方法要点 | 主要输出 |
|---|---|---|---|
| **单点往返与组批** | 三种机型对各服务区的最大安全载荷；货箱组批；三维精确前沿；返航余量灵敏度 | 解析载荷、FFD 装箱、动态规划精确前沿、ε-约束 | 载荷表、组批方案、Pareto 前沿、灵敏度曲线 |
| **多点多架次调度** | 多点访问顺序、机型指派、架次时刻；四目标权衡 | 固定种子构造 + 非支配分层遗传算法 + 局部打磨 | 四目标 Pareto 前沿、代表方案、九类约束检验 |
| **联合调度与中继** | 运输与中继的联合排程；五目标权衡；错峰与首批截止的冲突 | 分层编码 + 确定性中继 oracle；零中断作为准入条件 | 五目标 Pareto 前沿、六个代表方案、十七类约束检验 |
| **分区与资源核算** | 2/3 任务组分区、组内资源配置、资源缺口及原因 | 服务区原子 + 流式分区枚举 + 区间图峰值并发 + 缺口归因 | 分区方案、峰值并发、资源缺口与原因 |

其中**联合调度与中继**是主线，前三层为它提供组批基础、无通信基准与上游方案。

## 2. 快速开始

环境：Python 3.11（3.9+ 可用）、`numpy >= 2`、`scipy >= 1.15`、`matplotlib >= 3.10`。

```bash
pip install -r requirements.txt

# 四层任务
python 运行入口.py 最大安全载荷
python 运行入口.py 可行组批
python 运行入口.py 精确前沿
python 运行入口.py 余量灵敏度
python 运行入口.py 多目标优化
python 运行入口.py 运输方案检验
python 运行入口.py 预热缓存
python 运行入口.py 联合调度 --规模 标准
python 运行入口.py 联合方案检验
python 运行入口.py 分区配置
python 运行入口.py 资源缺口

# 按依赖顺序一次跑完（联合调度默认快速档）
python 运行入口.py 全部 --联合规模 快速
```

也可以直接运行任一主程序：

```bash
python "源代码/求解器/联合调度与中继/五目标优化/主程序.py" --规模 快速
```

**参考耗时**（24 逻辑核 / 8 进程，见 [标准档运行记录](结果/标准档_20261025/运行记录.md)）：

| 程序 | 墙钟 |
|---|---:|
| 最大安全载荷 / 可行组批 / 精确前沿 / 余量灵敏度 | 2 / 1 / 2 / 3 s |
| 多目标优化 / 运输方案检验 | 40 / 15 s |
| 预热缓存 | 约 5 min |
| 五目标优化（标准档）/ 联合方案检验 | 约 79 min / 约 3 min |
| 分区配置 / 资源缺口 | 3 / 1 s |

联合调度的规模档位为 `试跑 / 快速 / 标准 / 全量`；`标准` 为论文结果档位，建议先跑 `预热缓存`。

## 4. 求解器说明

### 4.1 单点往返与组批

- **最大安全载荷**：质量、可用装载体积、返航安全能量余量三重约束下的单架次最大投送质量。
- **可行组批**：货箱不可拆分，按质量降序首次适应递减（FFD）装箱，得到只求可行的组批方案。
- **精确前沿**：每个服务区用动态规划求（架次数、总能耗、累计作业时间）的精确 Pareto 前沿，再逐区合并；按 ε-约束给出给定架次上限下的前沿与三个端点解。
- **余量灵敏度**：返航余量 ρ 从 0% 到 50% 扫掠，观察最大安全载荷、受约束位置与组批指标的变化。

输出：`最大安全载荷.csv/json/md`、`组批方案.json/汇总.csv/逐架次.csv`、`Pareto前沿.csv`、`灵敏度_*.csv`。

### 4.2 多点多架次调度

- **多目标优化**：四个目标（加权总延误、全部任务完成时间、运输总能耗、架次数），固定种子构造 + 非支配分层遗传算法 + 局部打磨；硬约束包括载质量、体积、返航余量、无人机与共享电池不重叠、充电周转、医疗时限与首批截止。
- **方案检验**：不读取上游中间对象，只读 `代表方案.json`，独立重建载荷包、重新指派机型与调度，逐条检验九类约束。

输出：`Pareto前沿.csv`、`代表方案.json`、五个代表方案 CSV、`权衡分析.md`、`方案详情.json`、`资源可行性检验.md`。

### 4.3 联合调度与中继

- **五目标优化**：及时性、联合完成时间、联合总能耗、运输架次数、中继架次数；分层编码（外层组批/顺序/机型、中层受硬时限约束的错峰、内层确定性中继 oracle）。**零通信中断是准入条件**，不进入目标函数；搜索中用中断时长作为 Deb 约束违反量。
- **方案检验**：独立重建每个代表方案的运输与中继时序，检验十七类约束（通信保障、能源、充电周转、悬停站等）。

输出：`Pareto前沿.csv`、`代表方案.json`、六个代表方案 CSV、`权衡分析.md`、`自检记录.md`、`通信保障与可行性检验.md`。

### 4.4 分区与资源核算

- **分区配置**：以「同一运输架次涉及的服务区」为不可分割原子，流式枚举全部 2/3 分区，按运输架次极差等字典序取均衡方案；用区间图团数计算各组峰值并发资源需求。
- **资源缺口**：独立复算上游方案并逐位对照，提取紧约束团，用合并树分解给出缺口主因与补齐建议。

输出：`分区方案.json`、`服务区原子.csv`、`四方面比较.csv`、`资源缺口.json`、`资源缺口_逐资源.csv`、对应 `.md` 报告。

## 5. 公共库

| 库 | 职责 | 关键模块 |
|---|---|---|
| **基础内核** | 全局口径、数据读取、几何、飞行物理、载荷与组批 | `配置`、`数据读取`、`地理计算`、`飞行模型`、`载荷求解`、`组批求解`、`场景装配` |
| **运输调度** | 多点飞行、时限、资源与调度、构造启发式、多目标搜索 | `多点飞行模型`、`时限模型`、`资源模型`、`调度求解`、`构造启发式`、`多目标求解`、`并行评价` |
| **通信中继** | 通信链路、地形剖面、悬停高度、缺口解析、中继排程、联合求解 | `通信模型`、`通信剖面`、`悬停高度`、`缺口解析`、`中继驻留排程`、`联合调度求解` |
| **资源分区** | 区间图、峰值并发、服务区原子、分区枚举、资源核算与缺口归因 | `区间图`、`资源占用`、`服务区原子`、`分区枚举`、`资源核算`、`缺口归因` |

设计约束：

- 物理/通信公式只在公共库实现一次，求解器不重复写公式。
- `通信中继` 是联合调度的自含实现，包含运输侧副本，便于单独运行。
- 下游只读上游的 `输出/*.json`，不 import 上游求解器代码；每个下游程序都会独立重算并对照上游。

## 7. 输入数据

`数据/基础数据/无人机数据/json/`：

- `调度中心与服务区.json`：调度中心、服务区坐标/海拔/人口
- `运输无人机数据.json`：A/B/C 三型运输机的质量、航程、能耗、速度等参数
- `中继无人机数据.json`：中继机型参数与悬停上限
- `物资需求与配送时限.json`：货箱质量/体积、优先级、期望送达时间
- `通信链路参数.json`：发射功率、天线增益、接收门限、遮挡损耗等

`数据/基础数据/地理数据/` 提供 30 m DEM、村镇点位、水系与道路，供地形遮挡与通信剖面计算。

## 9. 可复现性设计

- **固定随机种子**：同一输入应得到同一输出。
- **独立复算**：下游不只继承上游数字，而是用自己的代码重算并逐位对照；偏差超过舍入误差即报错。
- **自检落盘**：每个主程序在控制台、`*.md`、`*.json` 三处写自检记录；失败抛 `RuntimeError`，不静默给出错误结果。
- **哈希清单**：`结果/标准档_20261025/哈希清单.csv` 记录标准档每个输出文件的字节数与 SHA-256。
- **缓存**：中继站解缓存按「悬停点 × 缺口位姿」记忆，跨运行有效；预热可显著缩短联合调度时间。
