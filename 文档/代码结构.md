## 2. 命名原则

1. **目录按功能命名，不按题号命名。**
   - 四个求解器目录分别对应四类任务：`单点往返与组批`、`多点多架次调度`、
     `联合调度与中继`、`分区与资源核算`。
2. **模块名直接表达语义，不使用编号前缀。**
   - 例如 `通信模型.py`、`中继模型.py`、`资源占用.py`。
   - 模块名本身就是语义，编号不再承载架构信息；分层由目录表达。
3. **主程序统一命名为 `主程序.py`。**
   - 每个任务目录一个入口，任务名由父目录表达。
   - 通过 `运行入口.py` 或直接 `python 源代码/求解器/.../主程序.py` 运行。
4. **中文命名、中文注释。**
   - 标识符、注释与自动生成的报告均保持中文；README 提供英文概述。

## 3. 四个领域库

| 库 | 职责 | 主要模块 |
|---|---|---|
| **基础内核** | 时间与能源物理规则、几何、数据读取、载荷与组批 | `飞行模型`、`地理计算`、`载荷求解`、`组批求解` |
| **运输调度** | 多点飞行、时限、资源、调度、构造启发式、多目标搜索 | `多点飞行模型`、`资源模型`、`构造启发式`、`多目标求解` |
| **通信中继** | 通信链路规则、两张预计算表、悬停高度、缺口解析、中继排程、联合求解 | `通信模型`、`通信剖面`、`悬停高度`、`缺口解析`、`中继驻留排程`、`联合调度求解` |
| **资源分区** | 区间图、峰值并发、服务区原子、分区枚举、资源缺口归因 | `区间图`、`资源占用`、`分区枚举`、`资源账` |

### 3.1 唯一口径来源

- 物理/通信公式只在公共库实现一次；求解器不自己写公式。
- `通信中继` 是联合调度的**自含实现**：它包含运输侧的副本，便于单独运行。
- `资源分区` 通过 `import` 复用 `通信中继.资源模型`，不复制公式。

## 4. 数据流

```
数据/基础数据
      │
      ▼
单点往返与组批  ──输出 JSON/CSV──▶  多点多架次调度
      │                                  │
      │                                  │ 代表方案.json
      │                                  ▼
      └──────────────▶  联合调度与中继（论文主线）
                              │
                              │ 代表方案.json
                              ▼
                        分区与资源核算
```

- 下游只读上游的 `输出/*.json`，不 import 上游求解器代码。
- 每个求解器都会独立重算并对照上游，偏差超出舍入误差即报错。

---

## 5. 输出位置

每个求解器的输出写在**自己的任务目录**下：

```
源代码/求解器/<任务>/<子任务>/输出/
├── *.csv
├── *.json
├── *.md
└── 图表/*.png, *.svg
```

参考结果在 `结果/参考结果/`；论文实验的最终结果建议写到 `结果/论文结果/`。

---

## 6. 路径与导入约定

- `源代码/项目路径.py` 是唯一路径入口；各库的 `配置.py` 从这里取 `项目根` 与数据目录。
- 求解器主程序在启动时把项目根加入 `sys.path`，因此可以用
  `python 源代码/求解器/.../主程序.py` 直接运行。
- 统一使用 `源代码.公共库.<领域>.<模块>` 绝对导入，不使用 `sys.path` 挂载。
